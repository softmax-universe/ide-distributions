# researcher

A research worker of the Softmax IDE. `research serve` starts Sessions of this profile to work Tasks, one
at a time per Task. The Session claims its Task (which creates its git worktree), works only there,
records what it learns as claims and Experiment runs, proposes follow-up Tasks and submissions
through its Task, waits through `task_wait` when something outside its control must happen, and
ends by completing the Task. It speaks only to the Orchestrator (`task_ask`), never to the user.

Everything it does lives in the shared package [`core/`](../core/README.md). This folder is the
Hermes distribution shell:

| File | What it is |
|---|---|
| `distribution.yaml` | The manifest: the variables `.env` must define (`env_requires`). |
| `config.yaml` | The shipped Hermes config: the default model (`moonshotai/kimi-k3.1-pro`, falling back to `z-ai/glm-5.3`; Kimi pinned to Moonshot's endpoint; the user changes it through the bridge), approvals off, no deny list, memory off, the `researcher` plugin and the `ide-researcher` toolset, pruning of old large tool results from 64,000 tokens, the Hermes `browser`, `connections`, `cronjob` and `todo` toolsets off, the terminal environment passthrough. |
| `SOUL.md` | The system prompt, generated by `uv run python tools/build_prompts.py --write`; do not edit by hand. |
| `plugins/researcher/` | The plugin entry (`plugin.yaml` lists the tools; `__init__.py` imports `research_core` from the path in `local/core-path.txt`). |
| `scripts/prepare.py` | Preparation after install or update. |
| `.no-bundled-skills` | Hermes installs only its essential `hermes-agent` skill; the profile's other skills come from `core/src/research_core/skills/` through `skills.external_dirs`. |
| `local/` | Written at preparation; not shipped. |

## Tools

23 tools, listed in `plugins/researcher/plugin.yaml`; `goal` and `directive` are read-only. A
Researcher cannot create Goals, submit or notify the user, and has no `github` tool;
it proposes Tasks and submissions through its own Task.

## Install

```bash
hermes profile install ~/ide-distributions/researcher --name researcher --yes
# write ~/.hermes/profiles/researcher/.env (see distribution.yaml env_requires); IDE_WORKSPACE
# must be the same path as the Orchestrator's
<hermes python> ~/.hermes/profiles/researcher/scripts/prepare.py \
  --source ~/ide-distributions/researcher --hermes $(command -v hermes)
```

Several Researcher Sessions run in this one profile. To run them in separate profiles instead,
install it again under other names (`researcher-1`, `researcher-2`) and set
`IDE_RESEARCHER_PROFILES` in the Orchestrator's `.env`. Run each profile's `prepare.py`; a Coworld
switch configures the sibling profiles too.
